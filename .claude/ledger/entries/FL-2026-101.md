## Incident

`find_matching_beats()` in `crud/trips.py` traversed POI to Beat via
`(POI)<-[:AT_POI]-(NarrativeBeat)`. But `AT_POI` goes ItineraryItem -> POI; the
correct edge is `(POI)-[:HAS_BEAT]->(NarrativeBeat)`. The query was syntactically
valid and silently returned zero rows, so every trip-generation integration test
failed with empty results and the bug looked like a data problem. Semantics that
matter here: `HAS_BEAT` = POI->Beat, `AT_POI` = ItineraryItem->POI,
`TAGGED_WITH` = Beat->Lens. The schema file is the source of truth; a wrong-direction
traversal never errors, it just quietly matches nothing.
