## Incident

`src/tour/claim_repetition.py` ships a two-stage cross-beat repetition detector. Every
meaning-level verdict it produces comes from `HaikuRedundancyJudge`, which **has never
executed against a live model**. All 32 unit tests inject `LabelledStubJudge`, a
hand-labelled offline oracle.

The mutation suite proves the pipeline *defers* to the judge (strip the entity signal and
the detector goes silent; give the judge two same-subject/different-fact sentences and it
clears them). Nothing proves the judge is *right*.

## What IS proven, and must not be conflated with what is not

STAGE 1 — `generate_candidates` — is validated on real data, at $0, against the live graph
corpus (105 sentences of `data/paris/tours/pont-neuf-60min-5afc2e.md`):

```
entity co-occurrence      : 1012 candidate pairs
4-gram Jaccard @ 0.18     :    0 pairs
Vert-Galant cluster       :  6/6 caught
'New Bridge/oldest' pair  :  caught (beat 4cb9c5a0 has entities=[])
```

That is the hard half — the half the lexical gate failed outright — and it is real.

STAGE 2 is unmeasured. A reader seeing the stage-1 numbers in a commit message could
easily conclude the detector as a whole is validated. It is not.

## Closing condition

A labelled bake-off on real Pont Neuf pairs, precision/recall against human labels,
mirroring `scripts/faithfulness_calibrate.py`. Cost ~$0.006 for one tour; requires
explicit user approval to spend per the standing credit-discipline rule.

Related: FL-2026-110 (serial critical path). See also the project memory note that
`content_budget` is harness-only — the same class of error, where evidence from one layer
was read as proving another.
