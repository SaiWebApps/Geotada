## Incident

`pytest.mark.skipif(not _neo4j_available(), ...)` conditions get evaluated at
import time and the compiled result lives in `__pycache__`. If the check once
returned False (container down, wrong env), the `.pyc` keeps serving that answer
even after the environment is fixed — editing `.env.test` does NOT re-evaluate
it, and the shell env can additionally shadow file values (precedence: shell env
-> process env -> load_dotenv() -> defaults). The symptom is integration tests
skipping "for no reason" while the database is demonstrably up, which has
previously escalated into sandbox-blame and connection debugging. `make
test-local` clears the cache as part of its sequence, which is why it is the
prescribed first move.
