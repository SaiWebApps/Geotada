## Acceptance criteria (verbatim, full list)

- **AC-1**: Given a uvicorn listening on 127.0.0.1:8000 and a separate process holding only a client connection to it, when the launcher's port-freeing step selects PIDs, then the set contains the listener PID and the listener is terminated.
- **AC-2** (negative): Given the same fixture, when the port-freeing step runs, then the CLIENT process is still alive (ps -p exits 0). No process whose only :8000 socket is client-side/ESTABLISHED/CLOSED/TIME_WAIT is ever signalled.
- **AC-3** (negative): Given Claude Helper PID 62717 holds two CLOSED client sockets to :8000, when make workbench runs to completion, then ps -p 62717 still exits 0. Capture lsof -i:8000 before and after.
- **AC-4**: Given only a client/CLOSED socket to :8000 exists, then scripts/deploy.py _port_busy(8000) returns False and _upload_areas_step proceeds past deploy.py:117.
- **AC-5**: Given the port-freeing step finds a process to kill, when it runs, then it prints the PID and command name before signalling. A silent kill fails this criterion.
- **AC-6**: make db-parity TARGET=local exits 0 with [OK] on POIs, beats, areas and POI->Area for all three cities.
- **AC-7**: Running scripts/ensure_dev_data.py TWICE consecutively exits 0 both times. A single green run does not satisfy this — the defect is that seeding re-creates the drift.
- **AC-8**: The dev graph has exactly 370 (:POI {city_name:'paris'}) nodes, exactly one with name_key 'cafe de flore', and zero with name_key 'café de flore'.
- **AC-9** (negative): git diff --stat -- data/ is EMPTY. Parity was not achieved by editing committed corpus data.
- **AC-11**: Given a dirty tree and the local opt-in set, when POST /api/v1/trips/preview runs for Paris, then candidate_eligible is true and compose_status is 'composed'. Build identity is never the reason for a downgrade.
- **AC-12** (negative): Given RENDER_GIT_COMMIT is set to a valid 40-hex SHA and the tree is dirty, the local dirty-tree allowance is NOT applied. The concession can never activate on Render.
- **AC-13** (negative): git diff -- src/tour/artifact.py shows no change to the BuildFingerprint field set.
- **AC-14**: With a clean tree and no env override, resolve_build_identity() still returns HEAD and still rejects a malformed GIT_COMMIT_SHA. Both branches asserted against a TEMPORARY git repo, never the ambient tree.
- **AC-15**: Given the premium path inside preview_trip's try block raises for any reason, then a WARNING-or-higher record on the 'ondoway' namespace names the exception type and message, with exc_info set. Exactly one record per request.
- **AC-16** (negative): An environment/config fault must NOT be reported as basic_tour.reason 'llm_generation_failed'. Two different causes must not produce byte-identical payloads; the build-fingerprint case yields code 'build_fingerprint_unavailable' and a detail containing the raised message.
- **AC-17**: grep -c candidate_rejection frontend/review.html is > 0, and in a real browser a preview returning candidate_eligible:false renders the code AND detail as visible text. Screenshot required.
- **AC-18**: AC-15/16/17 are provable with ZERO paid calls, using a pre-spend fault (resolve_build_identity runs at trips.py:1073, before _spend_precheck at :1074).
- **AC-23** (negative): Given a start point with no tourable corpus nearby, the renderTourRefusal card renders a readable reason — not a blank #tourStops, not a stuck spinner, not a silent success with zero stops.
- **AC-24**: The acceptance run makes at most TWO live Paris previews (each up to 8 Opus calls). A per-run cost estimate is printed and explicitly approved by the human BEFORE any live preview. Report the actual call count and spend.
