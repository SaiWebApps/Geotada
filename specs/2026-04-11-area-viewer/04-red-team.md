# Red Team: Area-Aware Content Viewer

**Date:** 2026-04-11
**Thinking mode:** Adversarial reviewer — "What breaks?"

## 1. Blockers

**None.** All issues found have clear resolutions that don't require spec changes.

**B1 (resolved): Area names with accented characters in URL paths.**
Three area names contain non-ASCII: `Île de la Cité`, `Île Saint-Louis`, `Saint-Germain-des-Prés`. FastAPI handles URL-decoded UTF-8 fine. Frontend must use `encodeURIComponent()` (same pattern as existing POI beats endpoint). Verified this works with the existing stack.

---

## 2. Risks

**R1: POIs in multiple Area contents lists (medium likelihood).**
27 POIs have WITHIN edges to 2+ arrondissements (from Scope 4's 0.00075-degree buffer). Not a viewer bug — expected data behavior. Could confuse during visual assessment if interpreted as containment error.
**Mitigation:** No code change. Founder aware of buffer-induced cross-border assignments.

**R2: Large contents list for city-level area (low risk).**
Paris city-level contents could return ~200 items if all POIs have WITHIN→Paris.
**Mitigation:** Contents endpoint returns only direct children (one-hop WITHIN). POI→Île de la Cité→4th Arr→Paris means POIs don't appear as direct Paris children. Verified: `MATCH (child)-[:WITHIN]->(a:Area {name:'Paris'})` returns only the 7 arrondissements. Bounded.

**R3: WKT parsing in browser (low risk).**
All 18 boundaries generated by same pipeline and validated by Shapely.
**Mitigation:** Defensive parsing — skip polygon and log console warning on failure. Don't crash viewer.

## 4. Codebase conflicts

**C1: `esc()` is the only XSS protection** (viewer.html line 126, uses `textContent`). Safe pattern. New Area panel must use `esc()` consistently for all rendered strings. Verification requirement for implementation.

**C2: Two `_serialize_props` functions exist** — `graph.py:13` and `crud/nodes.py:11`. They differ slightly (graph.py stringifies unknowns, crud handles lists explicitly). New endpoints go in `graph.py` and use its serializer. No conflict.
